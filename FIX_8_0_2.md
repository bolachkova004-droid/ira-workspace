# Исправление входа владельца — Rasmus 8.0.2

## Почему приложение не открывалось

GitHub Pages, Telegram-бот и webhook работали. Ошибка возникала дальше — при
привязке Telegram-владельца к кабинету в Supabase.

Старая логика предполагала только «идеально чистое» первое создание. Если в базе
уже оставался `admin`, основной workspace или пользователь без membership,
функция завершалась ошибкой. Дополнительно смена `is_primary` выполнялась одним
массовым `update`, который мог столкнуться с уникальным индексом до снятия флага
со старого кабинета. Настоящее сообщение SQL заменялось фразой «Не удалось
создать кабинет».

## Что исправлено

- добавлена миграция `202608130001_rasmus_beta_v802_owner_recovery.sql`;
- вход владельца из `OWNER_TELEGRAM_ID` стал повторяемым и самовосстанавливающимся;
- сохранённый legacy-workspace выбирается первым, данные учеников и уроков не удаляются;
- старый `primary` сначала снимается и лишь затем назначается нужный кабинет;
- отсутствующий membership создаётся повторно;
- настоящая серверная ошибка пишется в лог с коротким диагностическим кодом.

## Как применить

1. Загрузить всё содержимое архива в корень репозитория с заменой файлов.
2. Открыть GitHub → **Actions** → **Deploy Rasmus backend** → **Run workflow**.
3. Дождаться зелёного результата всего workflow.
4. Проверить `https://bolachkova004-droid.github.io/ira-workspace/health.json?v=802` —
   там должна быть версия `8.0.2-beta.1`.
5. Полностью закрыть окно Rasmus в Telegram, снова открыть бота и нажать
   **«Открыть Rasmus»**.

Если после этого появится сообщение с кодом, этот код можно найти в логах Edge
Function `telegram-auth`: теперь там будет точная причина вместо общей фразы.
