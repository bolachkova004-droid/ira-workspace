# Rasmus Beta 8.0.2 Owner Recovery — release notes

## Исправлено в 8.0.2

- Владелец из `OWNER_TELEGRAM_ID` больше не получает скрытую ошибку `platform_owner_already_exists` при повторной или частично завершённой настройке.
- Если запись администратора, membership и основной workspace разошлись, вход атомарно восстанавливает их связь и выбирает сохранённый legacy-кабинет в первую очередь.
- Переключение основного workspace сначала снимает прежний флаг, поэтому не конфликтует с уникальным индексом `workspaces_single_primary_idx`.
- Ошибка SQL теперь полностью записывается в серверный лог с коротким диагностическим кодом; пользователю не раскрываются служебные сведения.
- Восстановление идемпотентно: его безопасно запускать при каждом входе владельца, данные кабинета при этом не очищаются.

## Что изменилось

- Telegram `initData` проверяется сервером и обменивается на настоящую Supabase Auth session.
- Каждый преподаватель работает в отдельном workspace; доступ ко всем пользовательским таблицам ограничен membership-aware RLS.
- Общая beta-ссылка отключена. Приглашения преподавателей и учеников одноразовые, имеют срок действия и хранятся только как SHA-256 hash.
- Старые кабинеты и ревизии сохраняются при миграции v7 → v8. Автоматически владельцем становится только точный `OWNER_TELEGRAM_ID`.
- Ученический портал возвращает только расписание, оплату и домашнее задание; заметки преподавателя, цели, ошибки и внутренние идентификаторы не выдаются.
- Напоминания обрабатываются фоновым worker с атомарным захватом задания, retry/backoff и восстановлением зависших задач.
- Добавлены onboarding, beta feedback, сводка участников, безопасный сброс тестового кабинета и восстановление в течение 7 дней.
- Google Calendar подключается через OAuth; refresh token хранится в зашифрованном виде AES-GCM.
- GitHub Actions workflow применяет миграцию, разворачивает шесть Edge Functions, проверяет секреты, настраивает Telegram webhook и cron.

## Важное перед запуском

1. Сделайте экспорт production-базы и резервную копию текущего репозитория.
2. Укажите точный числовой `OWNER_TELEGRAM_ID` и отдельные случайные секреты согласно `CLOUD_SETUP.md`.
3. Выполните workflow и smoke-test владельца до отправки приглашений.
4. Старую общую ссылку `?start=beta` больше не используйте.

Текущая сборка: `8.0.2-beta.1`.
